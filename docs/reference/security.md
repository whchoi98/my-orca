## English

### 1. Overview
The only way in from outside is CloudFront, then an ALB whose security group admits only the CloudFront origin-facing prefix list and whose rules forward only when the `X-Custom-Secret` header matches, then the instance, which accepts ports 6768 and 6769 only from the ALB security group. In front of that path a CloudFront Function asks for an access password on every request, and Orca itself asks for a pairing link. The server is reached for administration through SSM, not SSH. Three kinds of values are credentials in this project and are never printed, logged or committed: the pairing link and pairing code, the one-time setup code, and the access password.

### 2. Components
| Component | Path | Purpose |
|---|---|---|
| Origin restriction | `infra-cdk/lib/orca-stack.ts` | ALB security group with one inbound rule (port 80 from the prefix list), listener created with `open: false`, default action 403 |
| Header secret and rules | `infra-cdk/lib/orca-front-door.ts` | 48-character random value in Secrets Manager; the origin header and the listener rules read it through a dynamic reference |
| Password gate | `infra-cdk/lib/functions/password-gate.js` | Checks the password hash, issues and verifies the signed `orca_gate` cookie, removes the cookie before the request goes to the origin |
| First-login setup | `infra-cdk/lib/gate/setup_service.py` | Accepts the first password only with the one-time setup code; locks after 20 wrong codes; logs the request line and status only |
| Setup service unit | `infra-cdk/lib/gate/install.sh` | Creates the setup code with mode 600 and runs the service with `NoNewPrivileges`, `ProtectSystem=strict` and write access to `/etc/orca` only |
| Password tool | `set_password.sh` | Stores only a salt, a hash and the signing key; the password is never a command-line argument; `--reset-ui` returns to first-login setup |
| Pairing link reader | `get_pairing_url.sh` | Uses an interactive SSM session, so the link is not kept in the SSM command history |
| Pairing outputs | `infra-cdk/lib/pairing/handler.py` | Returns the link as resource attributes for the stack outputs; its own log lines carry the state only |
| Pre-deployment checks | `deploy_orca.sh` | Stops an attach deployment when the host ALB security group is open to the internet; writes `cdk-outputs.json` with mode 600 |
| Host install | `infra-cdk/lib/host/install_orca.sh` | Checks the RPM against the sha256 digest of the release, refuses ports held by other programs, prints nothing secret |
| Commit check | `.claude/hooks/secret-scan.sh` | Blocks a commit that contains secret-like strings, environment identifiers or files that must not be committed. It reads what the commit will contain: staged files from the index, and the working-tree files that `commit -a`, a path given to `commit`, or `git add` on the same command line would add (ignored files named by `git add -f` included) |
| Session settings | `.claude/settings.json` | Deny and ask lists for Claude Code sessions in this repository |
| Terraform front door | `infra-tf/modules/front-door/main.tf` | Generates the header value with `random_password` (it stays in the state file) and stores it in Secrets Manager; keeps the setup bundle in a bucket with public access blocked and TLS only |
| Terraform deployment script | `deploy_orca_tf.sh` | Checks every security group of the host ALB, stops when the host already has an Orca deployment, and creates the state, plan and input files with umask 077 |
| SSM install helper | `infra-tf/scripts/ssm_run.sh` | Shell-quotes every input before it reaches the server and shows only the end of the script output |

### 3. Key Decisions
- The header value comes from Secrets Manager and appears in no template and no output. Only its ARN is an output (`OriginSecretArn`). This holds for the CDK stacks. In the Terraform deployment the value is generated by `random_password` and is in the state file in plain text, because the origin header and the listener rules take it as plain configuration. It is still not an output.
- A Terraform state file is a secret file. It is named `terraform.tfstate` and sits in the root module directory, since no backend is configured. `deploy_orca_tf.sh` and `cleanup.sh --tf` run Terraform with umask 077, the commit check and `.gitignore` refuse the state, plan and input files, and `.claude/settings.json` denies reading the state. A team that shares a deployment should move the state to an encrypted remote backend.
- The gate covers the UI, its assets and the WebSocket upgrade. The cookie is `HttpOnly`, `Secure` and `SameSite=Lax`, lasts seven days, and carries an expiry time signed with HMAC-SHA256.
- The password is stored as one SHA-256 over the salt and the password, and the edge cannot limit the request rate. A password of 12 characters or more is recommended, and AWS WAF with a rate-based rule is the way to narrow access further.
- The first password needs the one-time setup code, which exists only while no password is set. Before a password is set anyone who reaches the endpoint can lock the setup service with 20 wrong codes; a restart of `orca-gate-setup` clears the lock.
- The pairing link is server access. With the pairing output on, it is stored in plain text in the stack outputs, in the SSM Run Command history of the read command and in `cdk-outputs.json`. `deploy_orca.sh --no-pairing-output` keeps it out of all three. The Terraform deployment has no pairing output and no pairing resource, so the link is in none of them and is read only with `get_pairing_url.sh --tf`. Upstream release notes say a link stops working once the browser that used it has saved its own sign-in (Orca 1.4.254 and later); this was not tested here.
- Orca terminals and agents run as the server's user with the instance role. The dedicated stack gives that role SSM, CloudWatch agent and Bedrock invoke permissions. In attach mode Orca inherits the role of the host, so a broad host role turns a leaked link or password into leaked account permissions.
- The Lambda functions of the custom resources may call `ssm:SendCommand` only on one instance with the `AWS-RunShellScript` document. The Terraform deployment has no Lambda function: `infra-tf/scripts/ssm_run.sh` sends the command with the credentials of whoever runs Terraform.
- Rules for working sessions: never print or paste a pairing link, a pairing code, a setup code or the access password; never read `cdk-outputs.json` or a Terraform state file into a session, and do not run `terraform show` or `terraform state pull`, which print the state; pipe the output of a CDK deployment through a mask when a transcript is kept.
- Rules for committed files: no account ID, no ARN that contains one, no CloudFront domain, no instance, VPC or subnet ID, no email address. `cdk-outputs.json` and `infra-cdk/cdk.context.json` are not committed, and neither are the Terraform state, plan and input files under `infra-tf/`.

No ADR has been written yet. The design decisions are listed in `docs/architecture.md`.

## 한국어

### 1. 개요
외부에서 들어오는 길은 하나입니다. CloudFront를 지나, 보안 그룹이 CloudFront origin-facing 접두사 목록만 받고 `X-Custom-Secret` 헤더가 맞을 때만 전달하는 ALB를 거쳐, ALB 보안 그룹에서 오는 6768과 6769 포트만 받는 인스턴스에 닿습니다. 그 앞에서 CloudFront Function이 모든 요청에 접속 암호를 요구하고 Orca는 페어링 링크를 요구합니다. 서버 관리는 SSH가 아닌 SSM으로 합니다. 이 프로젝트에서 자격 증명으로 다루는 값은 세 가지이고 출력하거나 로그에 남기거나 커밋하지 않습니다. 페어링 링크와 페어링 코드, 1회용 설정 코드, 접속 암호입니다.

### 3. 주요 결정
- 헤더 값은 Secrets Manager에서 오고 템플릿과 출력 어디에도 나오지 않습니다. 출력에는 ARN만 있습니다(`OriginSecretArn`). 이것은 CDK 스택의 경우입니다. Terraform 배포에서는 `random_password`가 값을 만들고 상태 파일에 평문으로 들어갑니다. 오리진 헤더와 리스너 규칙이 이 값을 평문 설정으로 받기 때문입니다. 출력으로는 여전히 내보내지 않습니다.
- Terraform 상태 파일은 비밀 파일입니다. 이름은 `terraform.tfstate`이고 백엔드를 설정하지 않았으므로 루트 모듈 디렉터리에 있습니다. `deploy_orca_tf.sh`와 `cleanup.sh --tf`는 Terraform을 umask 077로 실행하고 커밋 전 검사와 `.gitignore`가 상태, 계획, 입력 값 파일을 막으며 `.claude/settings.json`이 상태 파일 읽기를 거부합니다. 배포를 함께 쓰는 팀은 상태를 암호화된 원격 백엔드로 옮깁니다.
- 게이트는 UI, 자산, WebSocket 업그레이드에 모두 적용됩니다. 쿠키는 `HttpOnly`, `Secure`, `SameSite=Lax`이고 7일 동안 유효하며 HMAC-SHA256으로 서명한 만료 시각을 담습니다.
- 암호는 salt와 암호에 SHA-256을 한 번 적용한 값으로 저장하고 엣지에서는 요청 횟수를 제한하지 못합니다. 12자 이상의 암호를 권하며 접근을 더 좁히려면 AWS WAF의 rate-based rule을 씁니다.
- 첫 암호에는 1회용 설정 코드가 필요하고 이 코드는 암호가 없는 동안에만 있습니다. 암호를 정하기 전에는 엔드포인트에 닿는 누구나 틀린 코드 20번으로 설정 서비스를 잠글 수 있습니다. `orca-gate-setup`을 재시작하면 잠금이 풀립니다.
- 페어링 링크는 서버 접근 권한입니다. 페어링 출력을 켜면 스택 출력, 조회 명령의 SSM Run Command 기록, `cdk-outputs.json`에 평문으로 남습니다. `deploy_orca.sh --no-pairing-output`은 세 곳 모두에서 뺍니다. Terraform 배포에는 페어링 출력과 페어링 리소스가 없어 링크가 이 세 곳 어디에도 남지 않고 `get_pairing_url.sh --tf`로만 읽습니다. upstream 릴리스 노트에 따르면 링크는 그 링크를 쓴 브라우저가 자기 로그인 정보를 저장하면 더 쓸 수 없습니다(Orca 1.4.254 이상). 여기서 시험하지는 않았습니다.
- Orca 터미널과 에이전트는 서버의 사용자와 인스턴스 역할로 실행됩니다. 전용 서버 스택은 그 역할에 SSM, CloudWatch 에이전트, Bedrock 호출 권한을 줍니다. 추가 방식에서는 호스트의 역할을 그대로 쓰므로, 호스트 역할이 넓으면 링크나 암호가 새는 것이 계정 권한이 새는 것과 같습니다.
- 커스텀 리소스의 Lambda 함수는 인스턴스 하나에 `AWS-RunShellScript` 문서로만 `ssm:SendCommand`를 호출합니다. Terraform 배포에는 Lambda 함수가 없고 `infra-tf/scripts/ssm_run.sh`가 Terraform을 실행하는 사람의 자격 증명으로 명령을 보냅니다.
- 작업 세션의 규칙: 페어링 링크, 페어링 코드, 설정 코드, 접속 암호를 출력하거나 붙여 넣지 않습니다. `cdk-outputs.json`과 Terraform 상태 파일을 세션에서 읽지 않고 상태를 그대로 출력하는 `terraform show`와 `terraform state pull`을 실행하지 않습니다. 기록이 남는 세션에서는 CDK 배포의 출력을 가리는 필터에 통과시킵니다.
- 커밋하는 파일의 규칙: 계정 ID, 계정 ID가 든 ARN, CloudFront 도메인, 인스턴스와 VPC와 서브넷 ID, 이메일 주소를 넣지 않습니다. `cdk-outputs.json`과 `infra-cdk/cdk.context.json`은 커밋하지 않고 `infra-tf/` 아래의 Terraform 상태, 계획, 입력 값 파일도 커밋하지 않습니다.
