# 변경 검토

지금 변경을 확신도 점수로 검토합니다.

## 1단계: 변경 찾기

- $ARGUMENTS에 파일이 있으면 그 파일을 봅니다
- 없으면 스테이징하지 않은 변경을 봅니다: `git diff`
- 그것도 없으면 스테이징한 변경을 봅니다: `git diff --cached`

## 2단계: 검토

바뀐 파일마다 `.claude/skills/project-review/SKILL.md`의 기준을 적용합니다.
- 프로젝트 관례(비밀 값과 환경 식별 값, 기존 서버에서 건드리면 안 되는 것)
- 파일 사이의 일관성(두 스택의 기본 버전, 두 곳의 패키지 목록, 스크립트 옵션과 README)
- 배포에 미치는 영향(설치가 다시 실행되는지, 실패했을 때 되돌릴 수 있는지)
- 버그와 품질

## 3단계: 점수와 거르기

문제마다 0에서 100으로 점수를 매기고 75 이상만 보고합니다.

## 4단계: 출력

파일 경로, 줄 번호, 수정 방법을 적습니다. 75 이상인 문제가 없으면 무엇을 확인했는지 짧게 적습니다. 코드를 읽어서 찾은 것과 실행해서 재현한 것을 나눠 적습니다.

## 막혔을 때

### 변경이 없을 때 (1단계)
- git 저장소가 아니면 `git diff`를 쓸 수 없습니다. 검토할 파일을 직접 지정해 달라고 합니다: `/review path/to/file`
- 이미 커밋했는지 봅니다: `git log -1 --oneline`

### CLAUDE.md를 읽을 수 없을 때 (2단계)
관례 없이 검토하면 근거가 없습니다. 파일이 있는지 확인하고 없으면 버그와 품질만 검토했다고 밝힙니다.

### 변경이 클 때
파일이 많으면 `infra-cdk/lib/`와 루트의 운영 스크립트처럼 배포에 영향이 큰 곳부터 보고, 나머지는 범위에서 뺐다고 적습니다.
